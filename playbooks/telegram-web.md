# Telegram Web — переписка с клиентами

## Вход
`https://web.telegram.org/k/` (K — веб-версия).
Логин по QR: **попроси пользователя отсканировать QR-код в приложении**. Скриншот QR в терминале
пользователь увидит плохо — попроси открыть Telegram Web в обычном браузере и войти самому,
либо напиши пользователю: «открой web.telegram.org, залогинься, скажи — продолжим».
Пока не залогинен — работать с перепиской нельзя.

## Структура
- Слева — список чатов (диалоги). У каждого видно имя, превью последнего сообщения, время, счётчик непрочитанных.
- Справа — переписка. Внизу — поле ввода.

## Чтение
- `browser snapshot` — даёт и элементы, и текст страницы. Текст чата виден в блоке «ТЕКСТ СТРАНИЦЫ».
- Чтобы прочитать конкретный диалог: `browser click` по ref с именем чата, потом `browser read`.
- Непрочитанные счётчики видны в списке — они и есть «новые заявки». Начни с них.

## Сканирование новых сообщений (рутина «что нового»)
1. `browser open https://web.telegram.org/k/` — если уже открыт, просто `browser snapshot`.
2. По списку чатов видны непрочитанные (счётчик рядом с именем). Собери их: имя, превью, счётчик.
3. `threads ingest` с платформой `telegram` и списком чатов — агент запишет, что нового и где.
4. Для чата с непрочитанными: `browser click` по имени чата → `browser read` → `threads append` с текстом
   последнего сообщения (direction `in`) → `threads markRead`.
5. Теперь у тебя есть список того, кому писать. Дальше — обычный цикл: прочитать переписку
   (`threads get`), ответить (черновик → подтверждение → `send_message`), записать ответ (`threads append`, direction `out`).

Не отвечай на сообщение, не прочитав переписку целиком: в чате бывает контекст в нескольких сообщениях.

## Отправка
1. Открой нужный чат.
2. `browser fill` — в поле ввода (`#message-input-textarea` или `textarea.input-message-input`).
   **Enter отправляет сообщение** в Telegram Web.
3. Отправка = необратимое действие, поэтому только через `send_message` с подтверждением.
   Инструмент сам найдёт поле, вставит текст и нажмёт Enter.
4. После отправки — `threads append` (direction `out`), чтобы помнить, что уже отвечал.

Если канал `manual` — агент только готовит текст, ты отправляешь сам.

## Правила
- Один чат — одно сообщение по делу. Никаких «здравствуйте, увидел ваш профиль, давайте сотрудничать»,
  если клиент сам не задал вопрос.
- Если клиент задал вопрос и ждёт ответа — отвечай в тот же день.
- Длинные тексты режь на 2–3 сообщения максимум, каждое — отдельным абзацем.
- Не обещай того, чего нет в профиле.
- Не спамь: 10 одинаковых сообщений разным людям — это не работа, а жалоба.
- После ответа клиенту — обнови заказ в пайплайне: `jobs update <id> {status: "replied"}` + заметка.

## Если что-то идёт не так
- Пропала авторизация → сообщи пользователю, попроси перелогиниться.
- Поле ввода не находится → сделай `snapshot`, найди textarea вручную, `browser fill` по ref.
- Отправилось не то → честно скажи и предложи вариант.
